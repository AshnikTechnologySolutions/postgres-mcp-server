# Grafana Dashboards

This folder contains starter dashboards for the local observability stack.

The richer Tempo experience described in Grafana’s Tempo docs is not just a dashboard. It relies on:

- Tempo Explore / TraceQL
- Service graph view
- span metrics and service graph metrics generated by Tempo metrics-generator
- a Prometheus datasource linked to the Tempo datasource

## Included dashboards

- `postgres-mcp-local-overview.json`
  - Tempo ingestion health from Prometheus
  - audit event rates by level and tool name from Loki
  - recent audit failures and recent audit events

## Recommended Grafana Tempo datasource settings

In your Tempo datasource, link Prometheus as the service graph / metrics backend.

If you provision datasources as YAML, the Tempo docs show the key shape as:

```yaml
jsonData:
  serviceMap:
    datasourceUid: prometheus
```

Once that is linked and Tempo metrics-generator is enabled, Grafana can show:

- Service Graph
- RED metrics from spans
- TraceQL-driven drilldowns

## Import steps

1. In Grafana, make sure these datasources exist:
   - Prometheus
   - Loki
   - Tempo
2. Open `Dashboards` -> `New` -> `Import`
3. Upload `postgres-mcp-local-overview.json`
4. When Grafana prompts for datasources:
   - map `DS_PROMETHEUS` to your Prometheus datasource
   - map `DS_LOKI` to your Loki datasource

## Suggested companion Explore queries

Use Tempo Explore with:

```traceql
{}
```

or:

```traceql
{ resource.service.name = "postgres-mcp-server" }
```

## Better workflow than a static dashboard

For a Tempo-style experience, use this workflow:

1. Use the overview dashboard for health signals
2. Open `Explore` -> `Tempo`
3. Use TraceQL to find traces
4. Use Service Graph to see topology and RED signals
5. Pivot from a trace to logs in Loki and metrics in Prometheus
